# MWD Monitoring App

## Overview

MWD Monitoring App adalah aplikasi web/PWA untuk central local server yang digunakan untuk monitoring data MWD/WITS, session/job, dashboard drilling, Rig WITS, historical data, well plot, export, admin/settings, service runtime, dan backup database.

Deployment final saat ini memakai satu server utama sebagai source of truth. User device lain mengakses aplikasi melalui browser atau app-mode shortcut ke server pada LAN.

## Architecture

```text
Industrial PC / Laptop Server Utama
├── PostgreSQL
├── Backend API Service
├── Frontend Web Service
├── Receiver / Gateway MWD-WITS
├── Logs
├── Backups
└── LAN URL

User Device
└── Browser / app-mode shortcut ke server
```

PostgreSQL hanya berjalan di server. Client LAN tidak boleh mengakses database langsung; semua akses melewati frontend dan backend API/WebSocket.

## Prerequisites

- Node.js.
- PostgreSQL.
- PowerShell.
- WinSW at `C:\Tools\winsw\WinSW-x64.exe` for service mode.
- Inno Setup 6 only when building/compiling installer.
- Correct `.env` generated by central deployment scripts.

## Environment Safety

- `.env` files contain credentials and must not be committed.
- PostgreSQL port `5432` must not be exposed to LAN clients.
- Logs, backups, dumps, generated package output, and local WinSW binaries must remain uncommitted.
- Frontend must use generated `NEXT_PUBLIC_*` values that match LocalOnly or LAN mode.
- If LAN IP changes, regenerate env and rebuild frontend.

## How to Run - LocalOnly

Use this mode for the server itself.

```powershell
npm run central:env:local
npm run central:start:local:build
npm run central:check:local
```

Open:

```text
http://127.0.0.1:3000
```

Do not mix `localhost` and `127.0.0.1` during cookie auth testing.

## How to Run - LAN Mode

Use this mode when other devices need access.

```powershell
npm run central:env:lan
npm run central:start:lan:build
npm run central:check:lan
```

Open from server or client device:

```text
http://192.168.18.75:3000
```

Operational notes:

- Keep server IP stable using DHCP reservation or static IP.
- If IP changes, regenerate LAN env and rebuild frontend.
- Do not expose PostgreSQL `5432`.

## How to Run - Windows Service Mode

Service manager: WinSW.

WinSW path:

```text
C:\Tools\winsw\WinSW-x64.exe
```

Commands:

```powershell
npm run central:services:dryrun
npm run central:services:install
npm run central:services:start
npm run central:services:check
npm run central:services:restart
npm run central:services:stop
```

Expected ready status:

```text
Backend service       : running
Frontend service      : running
Backend health        : OK
Frontend health       : OK
Final status          : READY
```

Do not run manual LocalOnly/LAN runtime at the same time as service mode.

## Backup and Restore

Manual backup:

```powershell
npm run central:backup:dryrun
npm run central:backup
```

Backup folder:

```text
backups/database
```

File format:

```text
mwd-db-backup-YYYYMMDD-HHMMSS.dump
```

Schedule daily backup:

```powershell
npm run central:backup:schedule:dryrun
npm run central:backup:schedule
```

Scheduled task:

```text
MWDMonitoringDailyDatabaseBackup
```

Restore:

```powershell
npm run central:restore:dryrun
```

Production restore is blocked unless explicit production restore confirmation is used. Do not restore production without an additional fresh backup.

## Testing Checklist

- LocalOnly: `npm run central:check:local`, login, dashboard.
- LAN: `npm run central:check:lan`, client device access, login, dashboard.
- Service mode: `npm run central:services:check`.
- Restart test: reboot server, wait 30-60 seconds, run `npm run central:services:check`, login from server and client.
- Backup: `npm run central:backup:dryrun`, then `npm run central:backup`.
- Scheduler: `npm run central:backup:schedule:dryrun`, then `npm run central:backup:schedule`.
- Installer: `npm run central:installer:check`, `npm run central:installer:compile:dryrun`; clean-machine install remains pending.
